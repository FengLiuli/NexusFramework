# 需求：Localization 本地化核心

## 0. 定位

本地化能力拆成两个库：

- **本文（R009）**：本地化核心——文本注册、按内容包分链、语言回退、查找。零 Config / Assets / Unity.Localization 依赖。
- **[R010](R010-localization-for-config.md)**：`LocalizationForConfig`——用配置表承载本地化条目，依赖本文与 R006。

拆分理由不只是"职责单一"：**孤儿检测需要读取目标内容包的表**（"这个翻译键在目标包里存在吗"），而核心库一旦依赖 Config 就无法再被独立使用。把"读表"留给适配器，核心只相信注册方。

> R008（内容包需求）尚未编写；本文与 R010 中涉及的清单字段、内容包启停通知，最终以 R008 为准。

---

## 一、背景

- 现有 [l10n.json](../../Assets/Demo/Table/Datas/l10n.json) 是 Demo 私有格式（`{"key","en","zh"}`），没有 Schema、没有运行时加载与查找，也没有多来源叠加；
- Unity Localization 是"一张表 + locale"模型，不支持按内容包分链、多包优先级叠加、第三方为其他包提供翻译；
- 多内容包（core / DLC / mod）与社区翻译要求：同一个文本键可能由多个来源提供，按"启用的内容包 + 优先级"裁决。

---

## 二、目标

1. 任意来源注册文本，运行时按 key 一次哈希查找；
2. 按**目标内容包**分链 + 语言回退，与内容包模型 C7 一致；
3. 核心零 Config / Assets 依赖，可被独立测试与复用；
4. 语言切换可重建，UI 通过事件获知。

---

## 三、术语

| 术语 | 定义 |
|---|---|
| **文本键** | 全局唯一字符串，格式 `<packId>:<path>`（`core:item.potion.name`），与数据包行键同构 |
| **目标内容包** | 文本键命名空间段所指向的内容包；链按它组织 |
| **本地化子包** | 一组 target + 一张多语言宽表 + 优先级；其内容由加载器/适配器注册 |
| **链** | 声明支持某目标内容包的所有来源，按优先级排序 |
| **预合并表** | 每个 `(目标内容包, 语言)` 预先合并好的一张字典 |
| **默认语言** | 游戏配置的兜底语言 |
| **上位语言** | `zh-CN` → `zh` 这类更宽的标签 |

---

## 四、需求

### A. 键与语言

- **RL1.** 文本键与数据包行键同构：`<packId>:<path>`，全小写，冒号为唯一分隔符，`path` 不含冒号。
- **RL2.** 支持的语言标签是 BCP 47 的**受控子集**；比较前做归一化（大小写、`_`/`-`）。不支持的标签在注册或设置时拒绝并诊断，不静默接受。
- **RL3.** 默认语言由游戏配置提供；未配置时按 `core` 内容包声明的默认语言，再退到 `en`。

### B. 注册

- **RL4.** 注册粒度：`(sourcePackId, targets[], priority, language, entries)`。`targets` 为精确 `packId` 列表；`entries` 为 `key → text`。
- **RL5.** 注册端与查询端接口分离：`ILocalizationRegistry` 只交给加载器/适配器；业务代码只能拿查询接口，避免运行期误注册。
- **RL6.** 同一 `(sourcePackId, language)` 再次注册视为**替换该来源的内容**（支持热重载）；不同来源互不干扰。
- **RL7.** 空字符串文本视为"未提供"：注册时跳过，查找时继续回退。"故意为空"需要显式标记（Q2）。
- **RL8.** 注册时校验 key 命名空间段是否属于 `targets`；不属于则拒绝该来源并给出键与期望 targets——键与声明不一致是可定位的错误，不应放行。

### C. 查找与回退

- **RL9.** 查找输入只有 `key` 与当前语言；目标内容包由 key 命名空间段确定，调用方不需要传 `packId`。
- **RL10.** 链的排序：按 `priority` 降序；同优先级按注册顺序，**后注册者优先**（稳定裁决）。
- **RL11.** 查找顺序：当前语言 → 上位语言（`zh-CN` → `zh`）→ 默认语言 → key 原文。
- **RL12.** 预合并：每个 `(目标内容包, 语言)` 构建一张字典，链按优先级从低到高写入、高者覆盖；查询为一次哈希。
- **RL13.** 重建时机：注册/替换、内容包启用状态变化、`SetLanguage`、默认语言变化。重建必须原子——查询线程不会读到半成品（实现用构建新表后原子替换引用）。
- **RL14.** 查询 API：`Get(key)`、`TryGet(key, out text)`、`Has(key)`、`Format(key, args)`（`string.Format` 语义），以及诊断用 `GetWithFallbackInfo(key, out sourcePackId, out language)`。
- **RL15.** 缺失记录：查找走到 key 原文时记录 `(key, language)`；提供 `DrainMissing()` 导出并清空，避免无界增长。

### D. 语言状态与事件

- **RL16.** `Language` / `DefaultLanguage` / `SetLanguage(tag)`；切换成功后发送 `LanguageChangedEvent`（struct，含旧、新标签）。
- **RL17.** 内容包启用/禁用由编排层通知（如 `NotifyTargetsChanged(targets)`），核心不主动扫描内容包、不读清单。
- **RL18.** 线程假设：注册、查询、切换均在主线程；不承诺多线程安全（Unity 主线程模型）。

### E. 质量与性能

- **RL19.** 程序集只依赖 Core；测试程序集可在零 Config 引用下构造注册与查找并全绿。
- **RL20.** 性能预算（需实测确认）：10 万条目 × 8 语言，预合并 ≤ 200 ms、常驻内存 ≤ 30 MB；字典命中查询 ≤ 100 ns/次。结果写入进度文档，超出预算时优先考虑按语言惰性构建。

## 五、验收示例

- **AE1. 基础查找（RL4, RL9, RL14）**：core 注册 `en` 与 `zh-CN` 两个来源；`Get("core:ui.confirm")` 在 `zh-CN` 下返回中文、切到 `en` 后返回英文。
- **AE2. 链覆盖（RL10, RL12）**：社区补丁（priority 200）注册同 key，查询返回补丁文本；补丁缺失的 key 回落至 core（priority 0）。
- **AE3. 语言回退（RL11）**：请求 `zh-CN` 时该条目只有 `zh` 列 → 返回 `zh` 文本；`zh` 也没有 → 返回默认语言文本。
- **AE4. 缺失到原文（RL11, RL15）**：整条链与默认语言都无此键 → 返回 key 原文，`DrainMissing()` 中包含该键。
- **AE5. 启用状态变化（RL13, RL17）**：禁用补丁内容包并通知后，链重建，查询回到 core 文本，且切换耗时可控。
- **AE6. 零依赖（RL19）**：测试程序集仅引用 Core + Localization，覆盖注册、覆盖、回退、缺失全链路。

## 六、范围边界

### 不做

- ICU 复数、性别、数字/日期本地化（使用 .NET 格式化，不做 CLDR）。
- 字体、排版、富文本解析、文本方向。
- UI 与语言选择界面（表现层）。
- 配置表读取、键存在性校验、覆盖率统计（R010）。
- 内容包发现、清单解析、生命周期（R008）。
- 翻译工作流工具与导入导出（Editor 工具，后续）。

### 明确假设

- 文本以 `string` 存放，不做流式或按需加载；超大数据量属于后续优化。

## 八、待决问题

- **Q1.** 受支持语言标签子集：是否包含 `zh-Hant`、`pt-BR` 等区域变体？建议固定一张表，注册与设置都以它为唯一来源。
- **Q2.** "故意为空"的标记形式：`~`、`\0`，还是注册时显式传入空值集合？
- **Q3.** `Format` 只支持索引占位符（`{0}`），还是也支持命名（`{name}`）？后者需要额外解析成本。
- **Q4.** 是否需要 `Get(packId, key)` 重载用于诊断（例如工具检查某包文本）。
- **Q5.** 目标包数量很多时，预合并表是否按语言惰性构建。
