# Config 与物品系统：需求边界裁决

## 摘要

对 [数据包子系统](../requirements/R006-data-pack-config.md) 与 [物品与存储子系统](../requirements/R007-item-storage.md) 的职责边界做合并审视。本文产出四件事：

- 两者是**消费关系**：物品消费 Config 的表能力，Config 对物品零知识；
- **15 项越界需求**归入 8 个其他归属域，不在两个模块里含糊保留；
- 两模块的跨模块契约固定为三个；
- 四个**框架核心缺口**需要在接口实现前决策。

> 本文的裁决已被 R006 / R007 采纳（§六 记录采纳结果）。后续如出现新的边界争议，在本文件追加，不另开新文档。

---

## 一、职责与依赖方向

```text
表现层（UI / 拾取表现）
      ↓
业务玩法（Loot / 经济 / 配方 / 耐久规则）
      ↓
内容包（数据包 / 资源包 / 本地化包 / 程序包）
      ↓                    ↘
NexusFramework.Config      NexusFramework.GAS
（表存储 · 多包合并 · 加载抽象）  （Tag · Attribute · Effect）
      ↓                    ↗
NexusFramework（Carrier · Trait · CarrierIndex · 事件 · IOC · 序列化）
      ↑
契约包 / SDK（对外 API，见内容包模型）
```

| 能力 | Config | 物品子系统 |
|---|---|---|
| 表数据存储与查询 | ✅ | 消费 |
| 多包行级合并 | ✅ | 消费（mod 物品表） |
| 数据源加载抽象 | ✅ | 不关心 |
| 物品定义语义（分类/堆叠/槽位） | ❌ 零知识 | ✅ |
| 物品实例与容器 | ❌ | ✅ |
| 物品操作与规则 | ❌ | ✅ |
| 物品事件 | ❌ | ✅ |
| 物品的序列化结构 | ❌ | ✅（只产快照） |
| 存档落盘/槽位/迁移 | ❌ | ❌ → 存档子系统 |
| 物品效果执行 | ❌ | ❌ → GAS |
| 服务注册与覆盖（程序包） | ❌ | 消费 IOC |

**依赖方向**：`物品 → Config`、`物品 → Core`、`物品 ⇢ GAS`（可选，经事件/接口）、`内容包 → 契约包`。**Config 不得反向依赖物品**。

## 二、重叠区裁决（7 项）

| # | 重叠点 | 归属 | 理由 |
|---|---|---|---|
| O1 | 物品定义表 | **Config 存，物品解释** | Config 只提供 `GetTable<TRow>("tbitem")`；字段语义与校验归物品 |
| O2 | 物品标签 | **物品定义存命名空间化字符串标签，GAS 提供匹配** | 物品不引 GAS 类型；`ITagMatcher` 经接口注入 |
| O3 | 名称与描述 | **Config 只存本地化 key** | 文本解析属本地化包 |
| O4 | 图标 | **Config 只存资源 key** | 资源加载属资源包 |
| O5 | 使用效果 | **物品扣数量并发事件；GAS 订阅执行** | 物品不知道 Effect 的存在 |
| O6 | 装备属性 | **物品发 `ItemEquippedEvent`；GAS 侧施加/移除** | 同上 |
| O7 | 物品存档 | **物品定义序列化结构；存档子系统负责落盘与迁移** | 避免物品模块承担 IO 与版本迁移 |

两处随主键体系修订的更新：

- O2 的标签不再是裸字符串，而是 `namespace:path` 形式的全局键；
- O3/O4 的 key 与行键同构（冒号分隔），解析方（本地化包 / 资源包）按命名空间路由。

### 四个框架核心缺口

1. **Carrier 序列化无 schema 版本号**：`CarrierManager.SaveToFile/LoadFromFile` 没有版本字段；物品走容器快照（自带版本）绕开，但其他载体仍受影响。
2. **CarrierId 的 TypeId 不可持久化**：`RegisterType` 用 `nextTypeId++` 惰性分配，`SerializeCarrier` 存的是完整 `RawValue`。自装 mod 改变注册顺序会导致读档后 TypeId 错位。**这是内容包（通道 B/C）的前置条件**——需要存档同时写 `typeName`，或让 TypeId 由稳定命名空间分配。
3. **无存档槽位/迁移机制**：属存档子系统。
4. **标签解析能力分散**：GAS 有 GameplayTag，Core 有 `TagKey/TagService`；物品定义存字符串标签 + 可选 `ITagMatcher`，但"三套标签"的收敛仍未决。

## 七、结论

1. **Config 与物品的需求已定稿**，实现顺序为 Config 先行、物品紧随；物品的定义访问以接口隔离，不阻塞实现。
2. **越界需求各自归位**，内容包与存档子系统不再是 Deferred 的垃圾桶：内容包已收口为模型，待 R008；存档子系统仍未建。
3. **主键与标识体系统一为命名空间字符串键**，贯穿表、物品、效果、词条、标签、资源与本地化 key。
4. **四个核心缺口里，CarrierId 的 TypeId 持久化是内容包的硬前置**，应优先于 R008 处理。
